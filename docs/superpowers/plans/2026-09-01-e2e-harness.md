# E2E Test Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command (`rewrite/scripts/e2e.sh`) drives the real Tauri app through WebDriver over every milestone 1–3 UI flow in an isolated environment. Milestone 3.5.

**Architecture:** Embedded WebDriver plugin behind an `e2e` cargo feature; `GRID_LAUNCHER_DATA_DIR` isolation override; a WebdriverIO project under `rewrite/e2e/` with a Node mock RomM server and stub emulators; a runner script wrapping build + Xvfb + dbus/keyring + wdio; a CI job.

**Tech Stack:** Existing workspace + `tauri-plugin-wdio-webdriver` (e2e feature only), `@wdio/cli` + `@wdio/tauri-service` + `@wdio/mocha-framework` (Node 22), xvfb-run/dbus-run-session/gnome-keyring (present on this machine). Versions resolved current at implementation (`cargo add`/`npm i -D`), no hand-pinned guesses.

**Spec:** `docs/superpowers/specs/2026-09-01-e2e-harness-design.md` — binding, incl. the release-build-never-contains-the-driver rule and the flow coverage contract table.

**Branch:** `rust-e2e` (already created, off `rust-launch`).

## Global Constraints

- The default (no-feature) build must never include `tauri-plugin-wdio-webdriver`; `tauri.conf.json` and `capabilities/default.json` are untouched; `withGlobalTauri` and the wdio permission live only in `tauri.e2e.conf.json` / `capabilities/e2e.json`.
- Fixture token literal everywhere: `FAKE-E2E-TOKEN-not-real`; allowed only under `rewrite/e2e/`; hygiene script must pass after every task.
- E2E state only under a per-run temp `GRID_LAUNCHER_DATA_DIR`; specs must never read/write the real `~/.config/grid-launcher`.
- Condition-based waits only (spec's flakiness policy); no bare sleeps except the documented reaper-window wait.
- All existing suites green at every commit; Python untouched. Commit each task with trailer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 4: Mock RomM server + fixtures

**Files:** Create `rewrite/e2e/mock-romm/server.mjs`, `rewrite/e2e/mock-romm/server.test.mjs`, `rewrite/e2e/fixtures/{platforms.json,roms.json,rom-details.json}`, fixture archives generated at runtime (see below)

**Requirements:**
- Plain `node:http`, ESM, no npm deps. Export `startMockRomm({port: 0, fixturesDir}) -> {port, close, requestLog}`; also runnable standalone (`node server.mjs --port 8931`).
- Auth: every /api route requires `Authorization: Bearer FAKE-E2E-TOKEN-not-real`; anything else → 401 JSON. Endpoints (mirroring what the Rust client calls — check grid-core/src/romm/mod.rs for exact paths/params): `GET /api/users/me` → `{id:1, username:"e2euser"}`; `GET /api/platforms` → fixtures (2 platforms, one named "Super Nintendo Entertainment System", one "Arcade"); `GET /api/roms?platform_ids=..&limit=..&offset=..` → paginated `{items:[...]}` from fixtures (≥3 games incl. one multi-file); `GET /api/roms/{id}` → detail with files list; `GET /api/roms/{id}/content/{file}?file_ids=..` → streams a zip built on the fly (a tiny valid zip containing `game.sfc` — build with `node:zlib`-free stored-entry zip writer, ~40 lines, or pregenerate once into fixtures at server start); cover endpoint path (whatever grid-core's covers.rs requests) → a 1x1 PNG.
- Request log: array of `{method, path}` retrievable and written to a file on close.
- `server.test.mjs` (node:test): auth rejection, pagination shape, zip content round-trip (unzip the streamed bytes with a minimal check of the local-file-header signature + name), users/me shape.
