A proposal: emulator setup and Windows game setup in one Systems tab under Settings, replacing the Emulators view. It starts as a new user, at Connect; Current app keeps today’s design for comparison.

Not built yet. Everything outside Settings › Systems matches Current app, except the notifications, and except that the top bar has four views (Ctrl+1 to Ctrl+4) and the Server header's emulator and firmware chips open Settings › Systems.

- **Fresh start:** Connect (server, username and password or API token, library folder; any values work here), then **Choose your systems**: the same rows as the Systems tab, with a tick box per system and the recommended emulator pre-selected once ticked. A system nothing can play shows "No emulator available" and can't be ticked; Windows (Linux only) picks the default Proton version: **Installed** lists what is already on the computer (system Wine, Proton installed by Steam, GRID's own downloads), **Download** lists the versions GRID can fetch with the recommended one (GE-Proton) first and pre-selected. The main button counts a Proton download with the emulators ("Install 3 emulators"), and reads "Continue" when only an installed Proton version was picked. Installing opens the app on Server with a card counting the installs, Proton included: "Setting up 3 installs · 1 done", then "3 installs done · 3 systems are ready to play". Its bar has one segment per install: filled when done, a moving fill while installing, empty while waiting; pointing at a segment names the install and its state; **Skip for now** opens it with nothing installed. Changes later happen in Settings › Systems. **Disconnect** in the server menu starts over.
- **Server › Discover** is the first Server rail row, with a divider under it, and the default view: the app (and first-run setup) opens on it. Preferred platforms are the systems with an emulator installed, Windows once a compat tool is picked for it (in setup or Settings › Systems), plus the games native to this computer's system, always included (Linux games on Linux; on a Windows computer, the Windows games).
  - **New releases:** a coverflow of the games on the preferred platforms released in the last six months, newest front and centre, at most 25. With none, the section says so and points to Settings › Systems. The centre cover is flat and lit; the others tilt 52° back, recede and dim, with a soft reflection. Arrows, a click on a side cover, or ← / → move it (450ms glide); a click on the centre cover (or Enter) opens Details. Under it: title, platform, release date, and Install or Play.
  - **Recently added:** the newest games on the server, leaving out the coverflow's (up to 8). A large screenshot on the left with title, platform, "Added 3 days ago" and Install or Play under it; on the right a column of small covers with their titles. The active row has a highlight frame that glides to the next row every 10 seconds (450ms) while the screenshot crossfades (600ms), wrapping at the end; a thin bar inside the frame fills over the 10 seconds. Pointing at the section pauses it; clicking a row jumps to it. Clicking the screenshot or the highlighted row opens Details; there are no Details buttons.
  - **Screenshots of another shape** (8:7, 4:3, 16:10, 21:9…) are fitted inside the 16:9 frame, uncropped, over a blurred, darkened, enlarged copy of the same screenshot, so the bars read as part of the picture.
  - **Logo, never plain text:** every game's title is a logo on the screenshot's bottom-left, over a soft dark fade; the caption has only the platform, "Added …" and Install. A game with a clear logo on the server shows it. Without one, GRID draws the title in one of three logo styles, coloured from the screenshot: it samples the screenshot's own pixels (never the blurred fill around an off-ratio shot), groups them into 4-bit-per-channel buckets, takes the most common bucket's average as the dominant shade, and uses a light tint of it (88% lightness) for the letters and a deep shade (16%) for the outline and shadow. The prototype's server logos are styled-text stand-ins in fixed colours (Windows, Linux, PS2, GameCube and two PlayStation games); the others are generated.
  - Release and added dates come from RomM (the game's release date and the date it reached the server); the prototype's are made up, and it adds Linux and Windows platforms. Native and Windows platforms show no emulator or firmware chips in their Server header.
- **One notification style:** every message (install results, launches, firmware, errors) is a card in a stack at the bottom right, above the download strip and over dialogs; the centred toasts are gone. Each card's Dismiss button has a bar along its bottom edge that runs down over 10 seconds, then the card closes itself; pointing at a card pauses it. The setup card counts down only once its installs are done. At most four cards stack; a fifth drops the oldest.
- **Server and Library headers fold while you scroll** (one shared behaviour). Past 32px of scroll the title, counts and chips fold up into the toolbar row, leaving the search field and Size (and Library's Sort) pinned to the top of the main panel; back within 8px of the top it unfolds (the gap stops flicker). The header floats over the grid, which reserves its unfolded height, so folding never moves a card. The fold takes 260ms (ease-out): the title row's height closes while it rises 8px and fades, the chips a beat ahead; the padding tightens from 14px to 8px; the bar turns to the opaque overlay surface with a soft shadow and a stronger edge, since it now floats over the covers. The search placeholder keeps the context: "Search PlayStation…" in Server; in Library "Search your library…", "Search recent games…", "Search games with updates…" or "Search <system>…". Switching system or filter starts the grid at the top, unfolded. Unfolding reverses it, the title fading in a moment late into the opening space. Reduced motion makes it instant.
- **Light / dark toggle** everywhere: a 28×28 icon button showing the current mode (sun or moon; its label names the switch, "Switch to dark mode"). On the startup screens it sits in the window's top-right corner (16px in); in the main window it moves into the top bar, left of the connection dot and username. A click switches the theme and sets Settings › Appearance › Theme to match ("Follow system" stays there); the icon spins in (300ms) and the colours ease across (240ms) instead of snapping; reduced motion makes both instant. The sun and moon are new icons on the app's 24-unit grid with its 1.5 stroke (paths in `docs/design/prototype/icons.json`).
- **Downloads** drops the legend line ("Active: downloading or installing · Queued: …"); the three section titles say enough.
- **Server header chips** follow the state: "Firmware: 3 files — no default emulator" until the system has an emulator, then "Firmware: 3 files", then "· installed".
- **One row per system on the server,** each with an emulator picker and a status: Ready, Update available, Firmware needed, Installing… or No emulator. Systems with no emulator come first, open, with a warning edge, the reason and one-click Install of the recommended emulator; a system no installable emulator plays says so and points to Add an emulator manually.
- **The picker is the installer.** It lists installed emulators that play the system, then an Install group with the rest, the recommended one first. Picking an Install option installs the emulator and makes it the system's emulator.
- **Install recommended (N)** in the header installs the recommended emulator for every system that has none. It replaces the first-run "Set up platforms…" picker, and hides when nothing is missing.
- **Opening a row** shows the emulator: version, Update (only when one is out), Open, and a ⋯ menu with Settings…, Show program folder and Remove (two clicks). The menu opens below the button, right-aligned, when it fits; near the bottom edge it opens beside the button (left, else right), shifted up to stay 8px inside the window. It never covers its button or opens upward over it, and it closes when the list scrolls. Below are the RetroArch core, the firmware line and the setup tips. An emulator used by several systems shows on each, and says which others it plays.
- **Pickers group their choices** under **Installed** and **Download**, the recommended one marked. **Windows** (Linux only) is a system row whose picker is the default Proton version, grouped the same way. Opening it shows the umu-run line and the first-launch note.
- **Add an emulator manually** sits in the header beside Install recommended, for an emulator GRID doesn't install; its form opens under the header. **Other emulators** at the bottom lists installed emulators no system uses. The settings sheet is the same for adding and editing: "Which emulator is it?", Program, Launch options, and cloud save fields under "Cloud saves (advanced)".
